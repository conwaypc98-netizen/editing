# Luna Editing Style Notes

Update this file only when the user explicitly asks to teach or save a repeatable editing rule.

Current default assumptions:

- The viewer should get to the useful tweak quickly.
- The edit should feel tight, direct, and proof-driven.
- Keep context only when it helps the viewer understand the tweak or trust the result.
- Cut obvious dead air, loading, repeated attempts, and long setup.
- Keep high-energy personality moments if they do not slow down the video.
- Do not blindly cut every pause; small natural pauses are fine.
- Remove worse duplicate takes caused by stutters, restarts, or repeated explanations.
- If a thought is said twice, keep the cleaner and more fluent version.
- Cut reference YouTube video watching unless it is essential context.
- Preserve chronological flow so the tweak/test/result sequence makes sense.
- Use word-level timestamps and waveform-aware cut points so the edit does not clip the end of spoken words.
- Leave a small spoken-word tail and use tiny audio-safe fades at joins to avoid static/click artifacts.
- Natural pauses are good, but awkward pauses should be shortened unless the viewer needs time to see an on-screen change.
- If the user asks to edit the intro, clean intro stutters and duplicate hook takes instead of preserving it.
- The user wants a very fluent, high-retention talking pace: remove obvious stutters and also remove small delays that make cuts feel stitched together.
- Treat held short words such as "it", "a", "and", "or", "so", and "the" as possible hidden pauses, even when the transcript text looks correct.
- Hook lists and intros should feel especially polished and tight; tighten list pauses unless the screen needs a beat.
- Future final passes should include a rendered transcript pacing audit and at least one revise/rerender loop when stutters or unnatural gaps remain.
- Use the saved Luna intro background image for spoken intro sections when requested: `assets/luna_intro_background.png`.
- The intro image should cover only the spoken hook/setup intro. Cut back to the screen recording when the tutorial/body begins and the viewer needs to see actions.

Feedback to capture over time:

- Preferred intro length.
- Whether to keep mistakes/funny moments.
- Whether the channel style wants captions throughout or only for emphasis.
- How aggressive jump cuts should feel.
- Preferred target duration by source length.
